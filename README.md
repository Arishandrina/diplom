# ВКР "Разработка методики оценки удельной бюджетной стоимости капитальных вложений в строительство школ ПФО по данным тендерной документации 2022-2025 гг. с применением языковых моделей"

Репозиторий к выпускной квалификационной работе: анализ закупок и контрактов на строительство школ по данным системы **МАРКЕР** (ПФО, 2022–2025), расчет сопоставимой удельной стоимости (руб./место), проверка гипотез и бенчмаркинг с использованием NLP/LLM для извлечения признаков из документации

**В Git** для промежуточных CSV, скачанных файлов и каталога `docs/` настроен `.gitignore` (исходные Excel «Реестр Торги…», папка `docs/`, все `*.csv` / `*.xlsx` в `data_processed/`)

---

## Структура кода

- **`pipeline/`** — подготовка выгрузок МАРКЕР, скачивание и парсинг документации, `fetch_eis_data.py`  
- **`analysis/`** — классификация, сборка датасета, гипотезы и вспомогательные эксперименты  

Рабочая директория ядра Jupyter: корень репозитория **или** папка `notebooks/...` (в ноутбуках корень ищется автоматически по наличию `data_processed/`).

---

## Рекомендуемый порядок запуска

1. pipeline / `marker_prepare.ipynb` → чистые таблицы по закупкам  
3. pipeline / `docs_download_marker_playwright.ipynb` → загрузка файлов в `docs/`  
4. pipeline / `docs_parse.ipynb` → признаки из документов  
5. analysis / `analysis_01_classify.ipynb` → отбор публикаций по типу работ  
7. analysis / `analysis_02_dataset.ipynb` → объекты и удельные показатели  
8. pipeline / `fetch_eis_data.py` → доп. признаки с ЕИС
9. analysis / `analysis_03_benchmark_hypotheses.ipynb` → удельная стоимость: бенчмаркинг, H1–H2, RCF и аномалии  
10. analysis / `analysis_04_h3h5.ipynb` → ограничительность (PCA), H3–H5  
11. analysis / `analysis_05_places_extraction.ipynb` → качество извлечения `places`

## `marker_prepare.ipynb`

**Задача.** Привести к единому виду выгрузки МАРКЕР (отчёты «Результаты» и «Цены»): парсинг Excel, восстановление гиперссылок там, где pandas их не читает, выбор строки с ценой победителя при нескольких строках на закупку

**Результат.** Таблицы «одна строка — одна закупка», участники, цены

**Файлы (в `data_processed/`):**  
`marker_results_main_clean.csv`, `marker_results_participants_clean.csv`

---

## `docs_download_marker_playwright.ipynb`

**Задача.** скачать тендерную документацию через браузер (**Playwright**): вход под учетной записью, переход по закупкам из `marker_results_main_clean.csv`, вкладка «Документация», сохранение файлов в `docs/<registry_number>__<purchase_code>/raw/`. ZIP/RAR распаковываются в процессе

**Результат.** Локальный архив документов для последующего парсинга

**Замечание.** В ячейках захардкожен абсолютный путь к проекту

---

## `docs_parse.ipynb`

**Задача.** Пройти по скачанным PDF/DOCX/DOC (и распакованным вложениям), извлечь текст и эвристиками/regex вытащить для каждой закупки:

- `places` — проектная мощность (мест); приоритет источников (название vs документы)
- `area_m2` — площадь
- `address_text` — адрес объекта
- `work_type_doc` — тип работ по документации (строительство / капремонт и т.д.)

Произведен аудит соотношения площадь/места, флаги подозрительных строк, списки пропусков по площади

**Файлы:** основной выход — `data_processed/marker_docs_parsed_auto.csv`. Дополнительно CSV аудита (`marker_docs_parse_audit_*.csv`, `marker_docs_area_missing_*.csv`).

**Вывод:** на всей выборке публикаций мощность извлекается почти всегда. Точность из текста документа у базового regex низкая. Улучшенный пайплайн и LLM разбираются в отдельном ноутбуке `analysis_05_places_extraction.ipynb`.

---

## `analysis_01_classify.ipynb`

**Задача.** По каждой публикации из `marker_results_main_clean.csv` — **LLM-классификация** типа работ (новое строительство, ПИР+СМР, ремонт, исключить и т.д.) и решение `include_base`: включать ли закупку в базовую выборку для строительства школ.

**Вход:** `marker_results_main_clean.csv`.  
**Выход:** `data_processed/marker_results_classified.csv`.

**Настройки:** ключ и endpoint задаются переменными (`LLM_API_KEY`, `LLM_API_BASE`, `LLM_MODEL`), используется модель Mistral

**Выводы:** из 157 публикаций в базовую выборку попадает **111**

---

## `analysis_02_dataset.ipynb`

**Задача.** Собрать рабочий датасет для регрессий и графиков:

- фильтр по `include_base` из классификации
- подтягивание цены победителя, НМЦК, участников
- слияние с `marker_docs_parsed_auto.csv` (места, площадь, адрес)
- дефлятор СМР по индексам Минстроя до базового квартала (`2025Q4`)
- агрегация публикаций в объекты строительства
- производные: удельная стоимость руб./место, скидки к НМЦК и пр.

**Выходы:**  
Рабочая таблица `analysis_objects_core.csv`. Ядро для эмпирики — объекты с сопоставимой удельной метрикой и контролями. Рабочая выборка порядка 55 объектов

## `fetch_eis_data.py`

**Задача.** Дополнить закупки признаками ограничительности:

1. Из уже подготовленного CSV МАРКЕР — нацрежим, тип торгов, проценты обеспечения заявки/контракта, банковское сопровождение (через merge по `registry_number`).  
2. Через **Selenium** (Chrome) — открыть страницы закупок на zakupki.gov.ru, в тексте страницы искать упоминание ПП № 2571 и формулировки про ограничение субподряда.

**Входы:** `data_processed/marker_results_main_clean.csv`, `data_processed/analysis_objects_core.csv`  
**Выход:** `data_processed/eis_restrictions.csv`

---

## `analysis_03_benchmark_hypotheses.ipynb`

**Задача.** Связать дефлированную удельную стоимость (руб./место) с факторами масштаба и торгов: описательная статистика и графики; **H1** — экономия на масштабе (корреляции, OLS в логах, Краскела–Уоллиса по регионам, Манна–Уитни по типу работ); **H2** — скидка от НМЦК и удельная стоимость; **RCF** (референсный класс сопоставимых объектов) и правило **Тьюки** для отметания выбросов по стоимости; качественный разбор выделенных кейсов.

**Вход:** в первую очередь `data_processed/analysis_objects_core.csv`  
**Выход:** таблицы и графики

**Выводы** **H1** частично подтверждается (масштаб значим, подгруппы по региону/типу работ при малом \(n\) — нет); **H2** на доступной подвыборке со скидкой значимой связи с удельной стоимостью не показано; по **RCF** выделяется порядка **7** аномалий из **55** объектов рабочей выборки (~13%)

---

## `analysis_04_h3h5.ipynb`

**Задача.** Индекс «ограничительности» документации и процедуры: из структурных полей МАРКЕР (обеспечения, инвертированный срок подачи заявок, банковское сопровождение и др.) строится матрица признаков, стандартизация и PCA → PC1 (финансовая нагрузка/барьеры) и PC2. Далее корреляции и регрессии с удельной стоимостью и мерами конкуренции — гипотезы **H3** (связь ограничительности со стоимостью и конкуренцией) и **H5** (медиация через конкуренцию)

**Входы:** `marker_results_main_clean.csv`, `analysis_objects_core.csv`, `eis_restrictions.csv`

**Выводы:** **H3b** для PC1 и скидки на торгах — значимая отрицательная связь на подвыборке со скидкой. Прямой связи PC с удельной стоимостью (**H3a**) и опоры для медиации (**H5**) нет

---

## `analysis_05_places_extraction.ipynb`

**Задача.** Оценить качество извлечения `places` из текста документов на ручной разметке (`places_validation_filled.csv`): сравнение baseline-regex, улучшенного regex, LLM на сниппете, LLM на полном тексте PDF, комбинированного пайплайна (title → LLM → regex …).

**Выводы:** на проверенной подвыборке общая точность baseline около **67%**, оптимальный комбинированный пайплайн — около **88%**
